# LIM — мини-приложение (MVP)

Каталог фермерских продуктов и оформление заказа с передачей в WhatsApp.
Реализовано по `PRD_LIM_MVP.md`: каталог → корзина → чек-аут → заказ уходит
менеджеру в WhatsApp и одновременно сохраняется на сервере, чтобы не потеряться,
если клиент не завершит переход в WhatsApp.

Без сборки и фреймворков: Node.js (встроенный `http`) + статический HTML/CSS/JS.
Один процесс, один VPS, без билд-шага.

## Быстрый старт

```bash
cp .env.example .env
# откройте .env и укажите свой номер WhatsApp и ADMIN_TOKEN
npm start
```

Каталог: http://localhost:3000
Админ-панель: http://localhost:3000/admin.html (токен — из `ADMIN_TOKEN`)

Для разработки с автоперезапуском: `npm run dev`.
Тесты: `npm test`.

## Структура

```
server/   backend (http-сервер, каталог, заказы, WhatsApp-ссылка, валидация)
public/   frontend (каталог, корзина, чек-аут, админ-панель) — без сборки
data/     catalog.seed.json — стартовый каталог; catalog.json/orders.json создаются рантаймом
test/     node:test — модульные и HTTP-тесты
```

## Как обновить каталог (без разработчика)

Два варианта, оба закрывают требование НФТ «нетехнический человек обновляет
каталог сам»:

1. **Админ-панель** (`/admin.html`) — открыть по токену, отредактировать
   название/цену/наличие/фото/историю фермера прямо в браузере, нажать
   «Сохранить каталог». Изменения видны клиентам сразу.
2. **Google Sheets** (опционально) — заполнить таблицу со столбцами
   `title, category, price, unit, farmer, story, description, image, inStock, sort`,
   опубликовать как CSV (Файл → Поделиться → Опубликовать в интернете → CSV)
   и указать ссылку в `CATALOG_SHEET_CSV_URL`. Сервер синхронизируется сам по
   таймеру (`CATALOG_SYNC_INTERVAL_MS`) либо по кнопке «Импорт из Google Sheets»
   в админ-панели.

Если ни один из вариантов не настроен, сервер работает на `data/catalog.seed.json`.

## Заказы

- Заказ сохраняется в `data/orders.json` **до** формирования ссылки на WhatsApp —
  так заказ не теряется, если клиент не успел или не смог перейти в чат.
- Каждому заказу присваивается номер вида `LIM-YYMMDD-NNN`.
- Сумма и состав заказа всегда пересчитываются на сервере по актуальному
  каталогу — клиент не может подменить цену в запросе.
- В админ-панели, вкладка «Заказы» — список заказов и выгрузка в CSV.
- Опционально: `ORDERS_WEBHOOK_URL` — URL Google Apps Script Web App, куда
  каждый заказ дублируется POST-запросом (для учёта в отдельной Google-таблице).

## Переменные окружения (`.env`)

| Переменная | Назначение |
|---|---|
| `PORT` | порт сервера |
| `WHATSAPP_PHONE` | номер менеджера для `wa.me`-ссылки, только цифры с кодом страны |
| `CURRENCY` | символ валюты в интерфейсе |
| `MIN_ORDER_AMOUNT` | минимальная сумма заказа (0 — без ограничения) |
| `ADMIN_TOKEN` | токен доступа к `/admin.html` и `/api/admin/*` |
| `CATALOG_SHEET_CSV_URL` | ссылка на опубликованный CSV Google Sheet (опционально) |
| `CATALOG_SYNC_INTERVAL_MS` | период автосинхронизации каталога из Sheets |
| `ORDERS_WEBHOOK_URL` | Apps Script Web App для дублирования заказов в Sheets (опционально) |

## Что осознанно не реализовано (см. PRD, п. 4.3)

Онлайн-оплата, нативные приложения, AI-бот, мультиязычность, логистика курьеров —
вне скоупа MVP.
